## 二、业务架构

### 2.1 业务全景（分层）

```
┌─ 管理决策层 ──────────────────────────────────────────────
│    数据标准与治理制度              治理成效评价
│
│                    │ 要求 / 考核
│                    ▼
├─ 业务执行层 ──────────────────────────────────────────────
│    物料新建            物料复用 / 借用            存量数据治理
│
│                    │ 触发
│                    ▼
├─ 数据治理层 ──────────────────────────────────────────────
│    名称规范 ─► 规格规范 ─► 分类一致性 ─► 同分类查重 ─► 编码统一
│
│                    │ 依托
│                    ▼
└─ 支撑层 ──────────────────────────────────────────────────
     PLM 系统          ERP          规则库 / 知识库        治理看板
```

| 层级 | 内容 |
|---|---|
| 管理决策层 | 标准与制度、成效评价 |
| 业务执行层 | 新建、复用、存量治理 |
| 数据治理层 | 名称 / 规格 / 分类 / 查重 / 编码 |
| 支撑层 | PLM、ERP、规则库、治理看板 |

### 2.2 核心业务流程

**（1）新建物料（源头治理）**

```
 开始：打开新建物料窗口
   │
   ▼
 ① 编码器：选大类 / 中类 / 小类 → 申请编码
   │
   ▼
 ② 编码回填到「编号」，分类随之确定
   │
   ▼
 ③ 录入「名称」「规格型号」
   │
   ▼
 ④ 校验（点击「校验并回填」）
   │
   ├────────────── 有错误 ──────────────┐
   │                                    │
   │ 通过                               ▼
   ▼                          名称 / 规格分栏提示
 ⑤ 采纳建议 或 选择相近物料             │
   │                                    │ 修改后重新校验
   ▼                                    │
 ⑥ 回填规范写法（名称 + 规格）          │
   │                                    │
   ▼                                    │
 ⑦ 保存 → 进入 PLM 后续流程             │
   │                                    │
   └────────────────────────────────────┘
```

要点：

- 分类由**编码**决定，编码由 PLM 编码器统一生成，治理环节不参与发号；
- 校验结果**分字段呈现**，名称的问题在名称处、规格的问题在规格处；
- 存在错误时**不允许回填**，需先修正或取消；
- 只有通过校验，才允许把规范写法写回页面。

**（2）存量治理（分批推进）**

```
 历史物料抽取
   │
   ▼
 批量体检
   │
   ├─► 名称不规范 ──┐
   ├─► 规格不统一 ──┤
   ├─► 分类与名称不符 ─┼─► 问题清单 + 整改建议
   └─► 疑似一物多号 ──┘        │
                               ▼
                        业务确认（谁在用、能否合并）
                               │
                               ▼
                         整改 → 复核 → 归档
```

### 2.3 角色与职责

| 角色 | 主要职责 | 在流程中的位置 |
|---|---|---|
| 设计/工艺人员 | 提出物料需求、确认名称与规格的准确性 | 新建与复用 |
| 采购人员 | 判断是否可复用、核对库存与在用情况 | 新建与复用 |
| 仓储人员 | 反馈实物与账面对应关系 | 存量治理 |
| 数据管理员 | 维护规则库、评估治理成效、组织存量整改 | 全流程 |
| 信息化中心 | 提供治理能力、保障集成稳定、持续优化规则 | 全流程 |

### 2.4 治理规则体系

| 规则类别 | 治理目标 | 提示方式 |
|---|---|---|
| 名称规范 | 名称只写“是什么”，不夹杂型号、参数、品牌 | 字段级提示 + 建议写法 |
| 规格规范 | 参数顺序、分隔符、空格写法统一 | 字段级提示 + 建议写法 |
| 分类一致性 | 名称与所选分类语义相符 | 提示更贴近的分类 |
| 同分类查重 | 减少重复建号，优先复用 | 提示相同/相近物料明细 |
| 编码统一 | 编码由 PLM 编码器统一生成 | 治理环节不介入 |

> 规则库与业务同步迭代：规则调整只需更新配置，不需要改动 PLM 页面与流程。

## 三、系统框架

### 3.1 总体框架

```
┌─ 业务用户 ────────────────────────────────────────────────
│     设计 / 采购 / 工艺 / 仓储
└───────────────────────┬───────────────────────────────────
                        │ 使用
                        ▼
┌─ PLM 系统 ────────────────────────────────────────────────
│     新建物料窗口   ·   物料编码器   ·   业务流与审批
└───────────────────────┬───────────────────────────────────
                        │ 提供入口 / 接收回填
                        ▼
┌─ 集成层（页面级增强）─────────────────────────────────────
│     校验与回填入口   ──►   字段映射与回填
└───────────────────────┬───────────────────────────────────
                        │ 请求 / 结果
                        ▼
┌─ 数据治理服务 ────────────────────────────────────────────
│     规则引擎   ·   分类识别   ·   查重与相似度   ·   物料索引
└───────────────────────┬───────────────────────────────────
                        │ 只读
                        ▼
┌─ 数据与配置 ──────────────────────────────────────────────
      治理规则库    ·    历史物料    ·    库存与业务信息
```

| 层 | 职责 |
|---|---|
| PLM 系统 | 提供页面、编码器、业务流；编码与保存仍由 PLM 负责 |
| 集成层 | 在页面上提供校验入口，把结果映射回名称/规格字段 |
| 数据治理服务 | 规则校验、分类识别、查重与相似度、物料索引 |
| 数据与配置 | 规则库、历史物料、库存与业务信息 |

### 3.2 组件职责

| 组件 | 职责 | 不做什么 |
|---|---|---|
| PLM 新建窗口 | 承载录入、触发编码器、最终保存 | 不内嵌治理逻辑 |
| 物料编码器 | 选择分类、生成并占用编码 | 不参与名称/规格校验 |
| 集成层 | 提供校验入口、呈现结果、回填字段 | 不改 PLM 页面模型、不改工作流 |
| 治理接口 | 统一接收校验请求、返回结构化结果 | 不发号、不写库 |
| 规则引擎 | 名称/规格书写规则、建议写法 | 不修改业务数据 |
| 分类识别 | 由编码推导分类、判断名称与分类是否相符 | 不改变编码规则 |
| 查重与相似度 | 同分类比对、相近物料排序 | 不自动合并、不自动建号 |
| 物料索引 | 历史物料检索底座 | 只读，不回写源系统 |
| 治理看板 | 存量体检、规则维护、成效查看 | 不介入 PLM 保存流程 |

### 3.4 部署视图

```
┌─ 用户侧 ──────────────────────────────────────────────────
│     浏览器：PLM 页面
└───────────────────────┬───────────────────────────────────
                        │ HTTP
        ┌───────────────┴────────────────┐
        ▼                                ▼
┌─ 应用侧 ──────────────┐      ┌─ 应用侧 ──────────────────┐
│     PLM 站点          │      │     数据治理服务          │
│     页面 / 编码器 /   │      │     规则 / 分类 / 查重    │
│     业务流            │      │                           │
└───────────┬───────────┘      └───────────┬───────────────┘
            │                              │ 只读
            └──────────────┬───────────────┘
                           ▼
┌─ 数据侧 ──────────────────────────────────────────────────
      ERP 数据库    ·    历史物料数据    ·    治理规则库
```

说明：

- PLM 站点与治理服务可**同机**也可**分离部署**，由配置决定访问地址；
- 治理服务对 ERP 与历史物料**只读**；
- 治理看板与治理服务可共用一套数据源。

### 3.5 集成边界（明确不改动的部分）

| 对象 | 处理方式 |
|---|---|
| 物料编码器 | **不介入**，编码仍由 PLM 统一生成与占用 |
| 页面模型 / 表单结构 | **不修改**，避免模型重新生成时被覆盖 |
| 业务流程与审批 | **不修改**，治理能力只做录入辅助 |
| 物料主数据写入 | **不越权**，最终保存仍由 PLM 完成 |
| ERP 数据 | **只读**，不回写 |

## 四、数据流与数据源

```
   编码器 ──► 编码（含分类）──┐
                              │
   名称/规格 ─────────────────┼──► 治理服务 ──► 规则结果
                              │        │
   规则库 ────────────────────┘        ├──► 分类与查重
                                       └──► 相近物料（含库存/项目）
```

| 数据 | 来源 | 使用方式 | 更新频率 |
|---|---|---|---|
| 治理规则 | 规则库（配置化） | 校验名称、规格、分类 | 按需调整，即时生效 |
| 历史物料 | 存量物料抽取 | 查重、相近物料、分类参考 | 周期性更新 |
| 库存与业务信息 | ERP | 相近物料的库存与最近业务参考 | 实时或准实时 |
| 编码与分类 | PLM 编码器 | 确定当前物料的分类上下文 | 每次录入实时获取 |

## 五、非功能与降级设计

| 关注点 | 设计原则 |
|---|---|
| 可用性 | 治理服务不可用时，PLM 录入与保存**不受影响**，仅提示不可用 |
| 性能 | 校验异步执行、输入防抖；结果返回前不阻塞页面操作 |
| 一致性 | 规则口径唯一，页面、看板、服务共用同一套规则 |
| 可维护性 | 规则配置化，调整不需要改页面、不需要发版 |
| 可追溯 | 操作留痕于浏览器控制台日志，关键结果可复现 |

## 六、演进路线

```
  一期              二期              三期              四期
 源头把关    ──►   存量清理    ──►   覆盖扩展    ──►   长效机制
   │                 │                 │                 │
 新建校验          批量体检          规则扩充          成效评价
 字段提示          问题分类          更多类型          标准迭代
 规范回填          整改建议          更多场景          常态化治理
```

| 阶段 | 目标 | 关键交付 |
|---|---|---|
| 一期 | 源头把关 | 新建窗口校验、字段级提示、规范写法回填 |
| 二期 | 存量清理 | 批量体检、问题分类、整改建议 |
| 三期 | 覆盖扩展 | 规则库扩充、更多物料类型与场景 |
| 四期 | 长效机制 | 成效评价、标准迭代、常态化治理 |

## 附录：术语

| 术语 | 含义 |
|---|---|
| 小类 | 物料分类的最小层级，与编码前段一一对应 |
| 规范写法 | 符合治理规则的名称/规格书写形式 |
| 相近物料 | 同一分类下规格写法接近的存量物料 |
| 一物多号 | 同一实物被重复建立多个物料编码 |
| 降级 | 治理能力不可用时，回退到 PLM 原生流程，不阻断业务 |
