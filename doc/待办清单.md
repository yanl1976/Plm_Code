### 13. 补齐 `.env` 的 PLM 查询配置 ⬜

**约束（硬性）**：只允许用 `.env` 的连接；**禁止访问 `198.168.6.15` 与生产库 `AIS20240102122641`**。

现状：`.env` 只有测试 ERP（`DB_SERVER=198.168.6.26`），**没有任何 PLM 查询配置**：

```
缺 PLM_BASE         PLM 站点地址（如 http://192.168.20.31）→ 走 WebAPI
缺 PLM_USER/PASSWORD  服务账号（服务端批量拉取时需要）
或缺 PLM_DB_*        PLM 主库 TCPLM 的独立连接（数据库直连方案）
```

三条可行路径（任选，均不碰生产库）：

| 路径 | 需要补的配置 | 适用 |
|---|---|---|
| **A. 插件内查询**（推荐先做） | 无（用页面登录态） | 实时查、数据最新；3100 不参与 |
| B. 3100 走 PLM WebAPI | `PLM_BASE` + `PLM_USER` + `PLM_PASSWORD` | 定期快照、无人值守 |
| C. 3100 直连 PLM 主库 | `PLM_DB_SERVER/USER/PASSWORD`（指向 `TCPLM`） | SQL 级对照，风险最高 |

### 14. 修正 `.env` 的 `SSH_HOST` 重复键 ⬜

```
SSH_HOST=192.168.20.31      ← 被覆盖
SSH_USER=yl
SSH_PASSWORD=***
SSH_HOST=192.168.30.135     ← 实际生效
SSH_USER=ng
SSH_PASSWORD=***
```

同一键出现两次，dotenv 取后者，前一组配置**永远不生效**。建议改为 `SSH_HOST_PLM` / `SSH_HOST_ERP` 之类区分用途。
