### 补充：编码归属与「待新增清单」定位（2026-11-19 现场确认）

- **正式物料编码一律由 PLM 编码器分配**：PLM 新增物料页点「编号」右侧「…」→ 在编码器里
  选大类/小类并申请编码；录入助手插件不参与发号、不改编号，只读取平台控件上的编码值
  （见 `doc/PLM物料录入助手_部署说明.md` 第 76、518 行）。
- 治理看板新增物料页顶部的「**预分配编码**」= 小类 6 位 + 5 位流水，由看板本地计算
  （`next-code` 取当前最大流水 + 1，提交时再审一遍占用并顺延）。它只是工位标识，
  **与 PLM 编码器实际分配的号码可能不同，不承诺一致**。
- 「待新增清单」（`data/new-materials.json`）**只是内部工作记录，不参与 PLM 建档**；
  其导出 Excel（按钮在「待新增清单」标题右侧 → `GET /api/new-material/export`）第 1 列
  「物料编码」即上述预分配号，仅供人工对照。
- 由此：该导出**不需要**与 PLM 导入模板列名对齐，列名保持「物料编码」不变；
  PLM 建档时以编码器分配的正式编号为准。

### detectSubMismatch 的判定顺序（9 步，命中即返回）

```
输入：名称 + 当前小类
  │
  ├─(1) 排除词：壳体/配件/支架/箱/钳/光缆组件… ──► 不判（是别的物）
  │
  ├─(2) 当前小类标准名被名称包含（"固定断路器"含"断路器"）──► 不判
  │
  ├─(3) 双归属豁免：当前类条数 ≥ 主导类 20% ──► 不判
  │       例「热缩管」101706 与 110404 各 120 条，两边都合法
  │
  ├─(4) 存量主导（name-sub-index.index）：
  │       某小类 ≥2 条且占该名称 ≥80% ──► 命中
  │       count ≥3 → error（红+阻断）；count =2 → warn（琥珀）
  │       例「电缆」802 条 @110302
  │
  ├─(5) 本小类无先例（name-sub-index.dist）：
  │       当前小类 0 条，别处 ≥2 条 ──► warn
  │       例「电源线」@100105 无先例，存量在 101604 插头(3)/110302 电缆(2)
  │
  ├─(6) 当前小类相似度已足够：Dice(名称, 当前小类名) ≥ 0.7 ──► 不判
  │       例「塑壳断路器」@100103 与「固定式塑壳断路器」
  │       ⚠ 这一步早期版本漏写在蓝图中，实际代码存在（minCurrent）
  │
  ├─(7) 前缀命中：名称以别的小类标准名/单元名开头 ──► error
  │       例「金属指示灯」@100105 → 101101 指示灯
  │       （参与结构比对的单元名只有标了 crossSub:true 的）
  │
  ├─(8) 短名称兜底（≤3 字）：名称是别的小类标准名/单元名的子串 ──► error
  │       例「端子」→ 101601 端子
  │
  └─(9) Dice 兜底：best ≥ 0.6 且领先当前类 0.25
          ≥0.9（blockBest）→ error；否则 → warn（阈值均可配）
```

**级别口径（重要 —— 曾因混用两套阈值导致同类提示两种颜色）**：

| 证据类型 | 判据 | 级别 |
|---|---|---|
| 存量主导 | count ≥3 且纯度 ≥80% | **error**（红 + 阻断） |
| 存量主导 | count =2 且纯度 ≥80% | warn（琥珀） |
| 本小类无先例 | 当前 0 条、别处 ≥2 条 | warn |
| 前缀命中 / 短名兜底 | 结构完全对应 | **error** |
| Dice 兜底 | ≥ blockBest(0.9) | **error** |
| Dice 兜底 | 0.6 ~ 0.9 | warn |

阈值全部在 `dedup-rules.json` 的 `subMismatch` 段：
`enabled` / `minBest`(0.6) / `minGap`(0.25) / `minCurrent`(0.7) / `blockBest`(0.9) / `level`(warn)。

> **口径原则**：能明确判定归属（存量主导、结构对应、高相似）→ 红色并阻断保存；
> 只是"疑似"（低频证据、中等相似）→ 琥珀且只提示。**不得跨语义复用阈值**。

### 4.1 段推进的三条特殊规则

段判定的默认逻辑是「某段填满 → 推进到下一段」，但有三种情况必须特判，否则会出现
「候选里推荐自己」或「Tab 连续追加一堆值」：

| 规则 | 触发场景 | 处理 |
|---|---|---|
| **型号段不自动推进** | 输入 `iC`、`NXB-6` | 型号是自由文本，只有打空格才算写完；否则 `iC` 恰好等于某个存量型号，会直接跳到极数 |
| **写完整才推进** | `3P␣`、`6` | 单参数段的值等于当前片段、或正好是该段候选值 → 视为写完（分断能力在存量里常写裸数字 `6`，正则提不到值） |
| **不回头提示已越过的段** | `3WT11H04 4P LSI/LSIG400A 50kA 690V␣` | 末尾是空格且该段早于已填满的段 → 返回空候选（`LSI` 不是 B/C/D 曲线，脱扣段被判空，回头提示会让 Tab 把 `C10A` 追加到末尾） |

### 4.2 规格框只补型号（onlyModel）—— 未启用（2026-11-19 核定）

```js
// src/server.js（分支保留，但当前没有调用方）
const onlyModel = url.searchParams.get('onlyModel') === '1'
if (onlyModel && r.param !== '型号') return { ...r, options: [], onlyModel: true }
```

**现状：未启用。** 接口分支保留（向后兼容），但「新增物料」页的规格型号框
（`public/app.js` 的 `nmSpecInput`）**不带** `onlyModel=1`，与业务执行端（PLM 录入助手插件）
的规格补全口径一致：按 PLM 存量规格的实际写法（型号 + 主参数混排）逐段给候选。

早期设计曾计划「规格只写型号、参数全部进主要参数框」，但 PLM 存量规格本身就是
「型号 + 极数/电流/分断」混排（如 `3WT11N04 4P LSI/LSIG400A 55kA 500V`），
验证端若强制只补型号，会与执行端看到的数据形态不一致、也无法验证真实录入场景。
若要重新启用，须同时评估对既有规格写法的影响后再改。

> 附加参数（接线能力、可选配件）**不参与规格补全**：它们不在 `param-standard.json`，
> 也不在 `naming-guide.fields` 里，只存在于 `accessory-dict.json`（见第六节）。

### 6.1 参数标准库（param-standard.json）

**核心原则：参数值按小类隔离，不跨类共用。**

```
电容的「额定电压」= 63V/100V/250V       断路器的「额定电压」= 220V/380V/690V
                                          ↓
若全局合并 → 63V 被推荐给断路器（业务上完全错误）
```

结构：

```jsonc
{
  "subs": {
    "100105": {
      "subName": "微型断路器", "rowCount": 849,
      "params": {
        "极数":   { "type": "enum",   "accepted": [{"value":"3P","count":229}, …], "aliases": {"3":"3P"} },
        "额定电压": { "type": "series", "series": "GB/T 156", "accepted": [ … ] }
      }
    }
  }
}
```

| 类型 | 判据 | 补全行为 |
|---|---|---|
| `enum` | 本小类取值 ≤15 种 | 直接给候选 |
| `semi` | 16–50 种 | 只给 Top N |
| `series` | 有国标序列（GB/T 156 / GB 1207 / E24…） | 存量值 + 本小类族标准序列 |
| `free` | >50 种（型号/阻值/容值） | 不推荐值，只留 Top5 参考 |

**三条硬规则**：

1. **值必须来自本小类**：读取接口 `standardValues(sub, name)` 强依赖 sub，不存在全局参数表
2. **标准序列按小类族选**：电容（1014xx）用耐压体系、电缆（1103xx）用电压等级、其余用 GB/T 156
3. **`±1%` 与 `1%` 是两个值**：GB/T 2691 规定允许偏差必须带 ±（±1% ≙ 字母代码 F），不自动等同

**管理与开关**：看板 →「命名规范 → 参数标准库」，可查看/编辑值清单、导入导出 JSON、切换 `enabled`/`shadow`。
构建：`npm run param:build`（从 `materials.ndjson` 重新生成）。

## 九、单位与字符规范

### 9.1 面积：`mm^2`（唯一四端全通）

| 写法 | Windows | Excel | PLM(NVARCHAR) | CAD(SHX) | 国标 |
|---|---|---|---|---|---|
| `mm²` | ✅ | ✅ | ✅ | ❌ 显示 `?` | ✅ 规范 |
| **`mm^2`** | ✅ | ✅ | ✅ | ✅ | ⚠ 排版受限替代 |
| `mm2` | ✅ | ✅ | ✅ | ✅ | ❌ 读作"毫米×2" |

选 `mm^2` 的依据：CAD/PLM 实际就这么写（现场确认），ASCII 全通，语义正确。

**统一链路**：

```
suggestSpec → unifySymbols（²→^2）→ material-rules.json 的 unitCase
            （mm2 / MM2 / m㎡ / ㎜2 → mm^2）→ struct-spec.js 的 normUnit（参数值也输出 mm^2）
```

**两个已修的坑**：

1. `unitCase` 曾有 `mm^ → mm^2`，右边界 `(?![A-Za-z])` 对紧接数字的 `^` 也成立
   → 把 `6mm^2` 改成 `6mm^22`。**已删除**。
2. 正则交替顺序：`mm` 排在 `mm^2` 之前 → `1mm^2` 被提取成 `1mm`。
   已改**长匹配优先**：`mm平方 → mm² → mm^2 → MM^2 → ㎜2 → mm2 → … → mm`。

### 9.2 体积：`m^3`，但**不动 `m3`**

| 写法 | 库内条数 | CP936 实际行为 | 处理 |
|---|---|---|---|
| `³`（U+00B3） | 0 | 降级为数字 `3` | → `^3` |
| `㎥`（U+33A5） | 0 | **变问号 `?`** | → `m^3` |
| `m3` | 75 | 正常 | **不动** |
| `M3`（螺纹） | 77 | 正常 | **绝不改动** |

> `m3` 与螺纹 `M3` 无法用正则可靠区分（`M3*12`、`BSO-M3-10`、`HFH-M3-8`），故 `m3` 不升级。
> 若将来要统一，只能按上下文（小类=水箱/体积类）单独处理。

### 9.3 直径：`Φ`（U+03A6）

库内混用 8 种：`Φ`(标准) / `φ` / `∅` / `∮` / `￠` / `Ф` / `Ø` / `ø`。

| 字符 | CP936 | 级别 |
|---|---|---|
| `∅` `Ø` `ø` | 真变问号 | must → `Φ` |
| `φ` `￠` `Ф` `∮` | 可显示但语义混用 | should → `Φ` |

**例外**：`cosφ`、`tgφ`、`PF=0.85(cosφ)` 里的 `φ` 是功率因数标准符号，**保留**。

### 9.4 字符表与引擎

`src/config/spec-symbols.json`：

```
replace（must 14 条）→ 会乱码/降级，必须替换
alias（should 8 条）→ 能显示但语义错或同义混用
whitelist（43 个）  → CP936 可表示且语义正确，保留
```

引擎：`unifySymbols(s)` 替换，`symbolIssues(s)` 产出提示（`checkSpec` 第 3 道）。
**该文件在 `spec.js` 模块加载时读取 → 改完必须重启 3130 与 3100。**

## 十、名称归一的三个层次（与查重的关系）

```
                 ┌─ ① 品类单元 nameUnits（209 个小类里已建 3 个）
名称归一优先级 ───┼─ ② 同义词字典 bySub / global
                 └─ ③ 不归一
```

| 层 | 数据 | 匹配方式 | 影响查重签名 |
|---|---|---|---|
| ① 单元名 | `naming-guide.subs[].nameUnits` | 精确 / 别名 | **是**（`dedup.js` 用 `matchUnit` 替换 FNAME 后再算签名） |
| ② 同义词 | `name-synonyms.json` | 前缀 / 后缀 / 模糊 | 否（只做候选与提示） |
| ③ — | — | — | 否 |

**形态保留原则**（自 `36fc222` 起）：

```
枪机 / 筒机 / 红外网络枪机 / 防爆枪机  → 枪型网络摄像机
球机 / 球型IP摄像机 / 普通球机          → 球型网络摄像机
半球 / 海螺型 / 海螺型PoE网络摄像机      → 半球网络摄像机
网络摄像机 / IP摄像机 / 测温摄像头（未标形态）→ 网络摄像机
```

> **判据：归一后能否凭「名称 + 规格」唯一确定买什么。**
> 120407 有 53%（68/128）的规格是纯型号，名称是形态的唯一载体 —— 所以必须拆开而非合并。

**职责边界**：建了单元的小类，不再在 `name-synonyms.json` 配同名条目（两套真源会分叉）；
未建单元的小类（120403 / 120404）才保留同义词通配。

### 11.4 新增一个品类单元

| 步骤 | 要点 |
|---|---|
| 1 | `naming-guide.subs[<小类>].nameUnits` 加 `{name, aliases, crossSub?, refined?}` |
| 2 | `crossSub: true` 的条件：该词能**唯一定位**本小类（`网线`、`插针`）<br>通用词（`机柜`/`支架`/`显示屏`/`电源适配器`/`插头`/`插座`）**不要标** |

### 11.5 新增一个附加参数系列

附加参数（接线能力 / 可选配件）**不进 `param-standard.json`**，走独立字典。新增步骤：

| 步骤 | 做法 |
|---|---|
| 1 | 把厂家样本放进 `data/selection/series/<小类>/<系列>.json`（或走「选型库」导入） |
| 2 | 确保样本含 `接线能力` / `可配附件`（或 `附件`）列 |
| 3 | 导入成功后 `buildAccessoryDict()` 自动重建，无需手工执行 |

> 一旦进了规格模板，它们就会出现在规格框的 Tab 候选里，又把配件带回规格，破坏一物多号查重。

## 十三、当前边界（已知缺口）

| 缺口 | 原因 | 影响 | 缓解 |
|---|---|---|---|
| 名称→小类判定对"库里散乱的新名称"无解 | 全库 5962 名称中 79% 频次 <3，无主导归属 | 新名称填错类时无提示 | 靠 `excludeHints` 业务词表补 |
| 规格模板中 `设备类型/关键参数/端头类型/螺栓孔径/接线方式/连接容量` 无补全 | 参数库无对应参数 | 这些段不弹候选 | 需先在 `spec-fields.json` 补参数 |

| 「其它」类（101808 947 / 120405 2129） | 兜底分类 | 交叉验证出 477 条疑似错类 | `docs/名称-小类交叉验证.xlsx`（A 级 108 条） |
| 插件端无灰字续写 | 平台控件为原生 input，叠加层跟随重绘风险高 | 仅候选条 + Tab | 需实测后再评估 |

| **组合段候选依赖参数齐全** | `{脱扣特性}{额定电流}` 需两参数都被提取 | 任一缺失则该段无候选 | 已用 `params.every()` 拦截空值 |

## 十四、一句话总览

> **三条链路、一个编排器、十一类配置、九步判定。**
>
> - 录入走 `checkMaterial`（名称 5 道 → 规格 3 道）与 `spec-complete`（模板分段 → 存量频次）
> - 批处理走 `extract → dedup → validate`，其中 `dedup` 产出的名称索引（index 1261 / dist 5961）
>   是跨类判定的数据基础 —— **不跑 dedup，第 4、5 步判定会静默失效**
> - 插件负责把 PLM 数据带回（快照），看板负责人工复核与规则维护，两者共用同一套规则引擎
>
> **三条铁律**：
> 1. 阈值不跨语义复用（存量占比 ≠ 字符串相似度）
> 2. 归一必须能凭「名称 + 规格」唯一确定买什么，否则拆而不是合
> 3. 明确归属才阻断（红），疑似只提示（琥珀）
