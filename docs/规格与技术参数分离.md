# 规格型号 / 主要参数 / 技术参数 的分工

> 记录「新增物料」页三个文本域的取值边界、数据来源与自动填充机制。
> 相关提交：`2a0fc1c` `db8a046` `ae7477d` `a53b12d` `0ffc85e` `501908c`

---

## 一、为什么要把它们分开

一物多号查重依赖**规格型号本身**。

```
GSW3-3200/3P                     ← 完整规格，查重签名的基础
```

如果把「防护等级 IP54」「可配附件 MO」这类内容也写进规格，会出现两个问题：

1. **同型号因配件不同而被判成不同物料** —— 恰恰是查重最需要拦住的情况
2. **签名被稀释** —— 配件写法的自由度远大于型号，近重判定失准

所以：**规格只写型号与主参数，附加说明与可选配件单独记录。**

## 二、字段对应

| 界面区域 | ERP 字段 | 存量有值 | 说明 |
|---|---|---|---|
| **规格型号** | `FSPECIFICATION` | 23,032 | 型号 + 主参数，查重、联想、补全都基于它 |
| **主要参数** | `F_ZXCV_ZYCS` | 2,759 | 主参数的另一种写法（业务已在用，非新造字段） |
| **技术参数** | 同上 `F_ZXCV_ZYCS` | — | 附加说明 + 可选配件，由选型库自动填入 |

> `ZYCS` = 主要参数（拼音首字母）。技术参数复用该字段，因为两者都是"规格之外的结构化补充"。

## 三、技术参数（附加参数）的数据流

```
选型库 Excel（厂家样本）
  data/selection/series/<小类>/<系列>.json
        │
        │  列「接线能力」「可配附件」「附件」
        ▼
src/accessory-dict.js  buildAccessoryDict()
        │  按「小类 + 系列」两级归类，解析「代号 中文」
        ▼
src/config/accessory-dict.json
        │
        │  GET /api/new-material/accessory-complete?sub=&model=
        ▼
前端 nmFillExtras()  →  #nmParams（技术参数框）
```

### 3.1 字典结构

```jsonc
{
  "wiring": [                                  // 接线能力
    { "sub": "100105", "series": "3WT",     "values": ["-（母排连接）"] },
    { "sub": "100105", "series": "NB8-40J", "values": ["1~16"] }
  ],
  "accessories": [                             // 可选配件
    { "sub": "100105", "series": "3WT", "code": "MO", "cn": "电动操作机构", "type": "标配" },
    { "sub": "100105", "series": "3WT", "code": "UVR", "cn": "欠压线圈",     "type": "选配" }
  ]
}
```

### 3.2 三个解析规则

| 源写法 | 解析结果 | 备注 |
|---|---|---|
| `MO 电动操作机构` | `code=MO` `cn=电动操作机构` | 代号 + 中文 |
| `S9/V9/XF9` | 三条独立代号，`cn` 为空 | Excel 里只给代号时 |
| `钢缆联锁` | `code=''` `cn=钢缆联锁` | 纯描述，无代号 |

编码损坏的片段（含 `\uFFFD`）直接跳过。

### 3.3 系列与通用

同一小类下不同品牌的配件**完全不同**：

```
100105 微型断路器
  ├─ 3WT（西门子）  → 母排连接 + MO/ST/CC/AUX/T40/UVR/UVR-t
  └─ NB8-40J（正泰）→ 1~16 + S9/V9/XF9/安装辅材
```

匹配规则（接口内 `hit`）：

```js
const S = String(series).toUpperCase()
if (!S) return true                          // 空 series = 通用，任何型号都返回
if (!model) return false
return model.includes(S) || S.includes(model)
```

- **系列名含中文**（如「螺栓选型清单」）在生成时会被置空 → 视为通用
  螺栓的配件（`GB/T 6170螺母 + 平垫圈`）与具体型号无关，不该按型号过滤
- **型号匹配不到任何系列** → 返回空，技术参数保持空白
  例：`iC65N`（施耐德）在 100105 的选型库里没有数据，就留空，不拿 3WT 的凑

## 四、前端填充的四个触发点

```js
// public/app.js
nmFillExtras()      // 唯一实现
```

| 触发 | 位置 | 场景 |
|---|---|---|
| 进入页面 | `loadNewMat()` | 首次打开「新增物料」 |
| 切换小类 | `onNmSubPicked()` | 换到另一个小类 |
| 手打规格 | `#nmSpec` input 防抖（180ms） | 手动输入型号 |
| 选型回填 / 点候选 | `nmSpecCheckOnly()` | 程序化改规格 |

> 最后一条是关键：`el.value = x` 不会触发 `input` 事件，
> 三条程序化路径（选型助手回填、点整条规格候选、点系列样例）都经过
> `nmSpecCheckOnly()`，所以在这里统一同步。

### 4.1 填充内容的格式

```
-（母排连接）、1~16、MO 电动操作机构、ST 分励脱扣、CC 合闸线圈、…
```

- **不含参数名**（「接线能力：」「可选配件：」是表头，不写进值）
- 同一参数内用 `、`，参数之间用 `；`
- 压成一行（原先是三行，换行被去掉后必须补分隔符）

### 4.2 用户改过就不再覆盖

```js
// 用户编辑技术参数（含删空）→ 打标记
$('#nmParams').addEventListener('input', () => { dataset.auto = '0' })

// 填充前检查
if (el.dataset.auto === '0') return
```

| 操作 | 结果 |
|---|---|
| 手动删改部分内容 | 后续改规格**不再覆盖** |
| 全部删空 | 保持空白，不回填 |
| 切换小类 | 重置标记，按新小类重新填 |
| 保存成功 | 清空并重置标记，下一条物料仍可自动填 |

`await` 请求返回后还会再查一次标记 —— 请求期间用户可能已经改过。

## 五、字典的自动重建

```js
// src/plm-server.js
const out = importSeries(body)
if (out.ok) {
  const st = buildAccessoryDict()          // 选型库变了就重建
  log('[accessory-dict] 已重建', JSON.stringify(st))
}
```

**选型库导入成功后自动重建**，无需人工跑脚本。

手工重建（改了解析规则或数据时）：

```bash
node -e "import('./src/accessory-dict.js').then(m=>console.log(m.buildAccessoryDict()))"
```

输出形如：

```js
{ wiring: 2, accessories: 28, series: 3, file: '.../src/config/accessory-dict.json' }
```

## 六、排障对照表

| 现象 | 原因 | 处理 |
|---|---|---|
| 技术参数整列是别的品牌的配件 | 字典漏了小类维度（早期缺陷） | 查 `accessory-dict.json` 的 `sub` 字段，重建 |
| 技术参数一直空 | 型号匹配不到任何系列 | 正常行为；需先把该系列导入选型库 |
| 选完小类就有内容 | 早期版本按小类汇总 | 现在要求型号非空才填，检查是否旧缓存 |
| 手动删掉后又被填回 | `dataset.auto` 标记失效 | 检查 `#nmParams` 的 input 监听是否绑定 |
| 选型助手回填后不更新 | 回填时的 `setTimeout(0)` 清掉了填充定时器 | 只作废联想（`sugSeq++`），不 `clearTimeout(nm.timer)` |
| 改了选型库但仍显示旧配件 | 字典未重建 | 重新导入一次，或手工执行上文命令 |

## 七、与规格补全的边界

**附加参数不进规格补全的候选。**

```js
// src/server.js（分支保留，当前无调用方）
const onlyModel = url.searchParams.get('onlyModel') === '1'
if (onlyModel && r.param !== '型号') return { ...r, options: [] }
```

> **2026-11-19 核定：`onlyModel` 未启用。** 新增物料页的规格框与执行端
> （PLM 录入助手插件）保持一致——按 PLM 存量规格的实际写法逐段给候选
> （型号 + 极数/电流/分断混排），不再强制「只补型号」。
> 早期「规格只写型号」的设想与存量数据形态不符，验证端强制启用反而无法验证真实场景；
> 如后续要启用，需先统一存量规格写法。

参数标准库与命名范式的 `fields` 里**都没有**「接线能力 / 可配附件」：

```
扫描 209 个小类：
  fields / 模板含第二类参数的小类   0 个
  参数库含第二类参数的小类          0 个
```

它们只存在于 `accessory-dict.json`，与 `param-standard.json` 完全隔离。
