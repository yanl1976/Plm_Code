# 规格型号字符标准（单位符号统一）

- 更新时间：2026-11-16 09:54:13
- 适用范围：物料「型号规格 / 技术参数 / 主要参数」等文本字段
- 兼容底线：**GBK / CP936**，并要求在 Windows、Excel、金蝶 PLM、AutoCAD 四端一致
- 配置位置：`src/config/spec-symbols.json`（**改后需重启服务**，该文件在 `src/spec.js` 启动时读取）

## 一、平方/立方：统一为 `mm^2`（关键决策）

| 写法 | Windows | Excel | PLM(NVARCHAR) | CAD(SHX字形) | 国标 |
|---|---|---|---|---|---|
| `mm²` | ✅ | ✅ | ✅ | ❌ 显示为 ? | ✅ 规范 |
| **`mm^2`** | ✅ | ✅ | ✅ | ✅ | ⚠️ 排版受限替代 |
| `mm2` | ✅ | ✅ | ✅ | ✅ | ❌ 会被读成「毫米×2」 |

**国标依据**：GB 3100-1993（单位符号用正体、整体使用）；GB 3101-1993 3.2.2（用 `m·s⁻¹` 表达幂）、
3.2.3（词头构成的新单位符号可取正负幂）；GB 3102.1-1993（面积单位 `m²`、导出单位 `mm²`）。
即国标要求幂用上标，`mm2` 不符规范。

**选 `mm^2` 的理由**：① CAD 的 SHX 字形只覆盖 GBK 双字节，不含 ²（显示为 `?`）；
② CAD 与 PLM 现行写法就是 `mm^2`，硬改 `mm²` 会造成图纸与系统数据不一致；
③ 纯 ASCII，四端全通，`^` 明确表示幂，语义与国标一致；④ `mm2` 排除（读作"毫米×2"）。

## 一（补）、立方单位：`m^3` 与螺纹 `M3` 的区分

库内实测（全库 23059 条规格）：

| 写法 | 条数 | 说明 |
|---|---|---|
| `³`（U+00B3 上标立方） | **0 条** | 库里无人使用 |
| `㎥`（U+33A5 兼容立方米） | **0 条** | 同上 |
| `m3` | 75 条 | **全是螺纹 M3**（`M3*12`、`BSO-M3-10`），不是立方米 |
| 「立方米」中文 | 2 条 | 仅水箱：`4立方米`、`12立方米` |

CP936 实测：`³` → `0x33`（降级为数字 3，非乱码）；`㎥` → `0x3F`（**真变问号**）。

**处理规则**：

| 输入 | 处理 | 理由 |
|---|---|---|
| `m³` / `³` | → `m^3` / `^3` | 上标唯一，安全 |
| `㎥` | → `m^3` | CP936 变问号，必须改 |
| `m3`（小写） | **不改** | 与螺纹 M3 无法用正则区分 |
| `M3`（螺纹） | **绝不动** | 库内 77 条螺纹规格，误改会破坏 |
| 「立方米」中文 | 保留 | 中文写法可接受，阅读无损 |

> 关键陷阱：库内 `M3*12`、`M3-8`、`BSO-M3-10`、`HFH-M3-8` 这类螺纹规格 77 条，
> 若做 `m3 → m^3` 的全局替换会全部改坏。因此只处理上标 `³` 与 `㎥`，不碰 `m3`。

## 六、批量处理建议

| 批次 | 范围 | 条数 | 风险 |
|---|---|---|---|
| 1 | `∅→Φ` | 111 | 低（纯符号替换） |
| 2 | `º→°` + 空格/连接符类 | 46 | 低 |
| 3 | `²→^2`（面积单位） | 89 | 低（整批统一） |
| 4 | `φ/￠/Ф/∮→Φ`（直径） | 106 | **中**：需确认确为直径（个别可能是型号字符） |
| 5 | `㎜→mm`、`㎡→m2`、`Δ→△` | 25 | 低 |

**流程**：导出清单 → 在 PLM 内按批次批量修改（或由 DBA 按清单执行 UPDATE 并审核）→ 重跑 `npm run extract && npm run dedup` → 看板与查重生效。

## 七、落地方式（引擎侧）

1. **建议写法 `suggestSpec`**：`6mm²` / `6mm2` / `6MM2` / `25m㎡` / `1.5㎜2` → `6mm^2` / `25mm^2` / `1.5mm^2`；`∅20` → `Φ20`；`200ºC` → `200°C`；`耐压1140∨` → `耐压1140V`
2. **录入校验 `checkSpec`**（不阻断）：「含 GBK/CP936 不支持的字符（Excel/PLM/CAD 间会乱码）：∅→Φ」「字符写法应统一：²→^2、㎜→mm、∨→V」
3. **单位大小写表 `material-rules.spec.unitCase`**：`mm² / MM² / mm2 / MM2 / mm^2 / m㎡` → `mm^2`
4. **范式库**：13 处模板/示例已改为 `mm^2`

## 八、修掉的一个隐藏缺陷

`unitCase` 里原有 `mm^ → mm^2` 规则（本意补全残缺写法），其右边界 `(?![A-Za-z])` 对正确的 `mm^2` 也成立
（`^` 后是数字 `2`），导致 `6mm^2` 被改写成 `6mm^22`。已删除该规则。

## 九、未处理与边界

- **不改存量数据**：清单只做提示与建议，修改需在 PLM 内确认后执行。
- **不参与查重签名**：`normalize()` 未改，查重簇数保持 541 不变。
- **西里尔/希腊混形字符**（`DС` 的 С U+0421、`DQM-II/Ι` 的 Ι U+0399）：视觉与拉丁字母相同，无法可靠区分笔误与原文，需人工判断。

## 十、维护

- 调整字符：改 `spec-symbols.json` 的 `replace` / `alias` / `whitelist`，然后**重启服务**。
- 重新生成清单：扫 `data/materials.ndjson`，用 `symbolIssues()` 判级、`unifySymbols()` 出修正值。
