# 规格型号字符标准（单位符号统一）

- 生成时间：2026-11-16 09:38:30
- 适用范围：物料「型号规格 / 技术参数 / 主要参数」等文本字段
- 兼容底线：**GBK / CP936** —— Windows 中文版、Excel 默认编码、金蝶 PLM 接口、CAD SHX 字形的共同交集
- 配置位置：`src/config/spec-symbols.json`（改后需重启服务；`src/spec.js` 启动时读取）

## 一、为什么以 GBK 为底线

| 端 | 约束 |
|---|---|
| Windows 中文版 | 默认 ANSI 代码页 CP936，非 GBK 字符在记事本/老程序里显示为方块或 ? |
| Excel（.csv / 老版 xls） | 另存为 CSV 默认 CP936，非 GBK 字符直接丢；xlsx 虽为 UTF-16，但经 CSV 中转仍会丢 |
| 金蝶 PLM | 接口/导入模板多为 GBK 字段，超集字符会被替换为 ? |
| AutoCAD | DWG 文本为 Unicode，但多数企业用 SHX 字体渲染，SHX 只覆盖 GBK 双字节，Unicode 私有符号会显示为 ? |

实测（CP936 往返编解码）两个最常见的坑：

- **`²`（U+00B2 上标平方）不在 CP936** —— 所有 `mm²` 写法在 GBK 环节会变成 `mm?`
- **`∅`（U+2205 空集符号）不在 CP936** —— 被当作直径符号使用时会丢

## 四、允许保留的符号（白名单，均已验证 CP936 可表示）

说明：全角括号 `（）` 保留（附件描述常用），是否改半角由既有规则 `bracketToHalf` 单独提示；
罗马数字 `Ⅰ Ⅱ Ⅲ Ⅴ Ⅸ` 保留（型号必须，如 BH-0.66 30Ⅰ）；`△` 保留（三相接法）。

## 六、落地方式

1. **建议写法（`suggestSpec`）** —— 用户输入原始写法，系统给出统一后的规范写法：
   `∅20 → Φ20`、`ZR-BVR 6mm² → ZR-BVR 6mm2`、`1*1.5㎜2 → 1*1.5mm2`、`耐压1140∨ → 耐压1140V`
2. **录入校验（`checkSpec`）** —— 不阻断保存，给出两级提示：
   - 灰/黄字：`含 GBK/CP936 不支持的字符（Excel/PLM/CAD 间会乱码）：²→2`
   - 灰/黄字：`字符写法应统一：㎜→mm、∨→V`
3. **单位大小写表修正**：`material-rules.spec.unitCase` 原先会把 `mm2` 转成 `mm²`，现已反向：
   `mm² / MM2 / mm^2 / m㎡ / mm^` 一律落成 **`mm2`**。
4. **范式库同步**：`naming-guide.json` 中 6 处 `specPattern` 的 `mm²` 已改为 `mm2`（101601、101606、101809、110301、110302、120203）。

## 七、未做与边界

- **不改存量数据**：246 + 131 条只做提示与建议，实际修改需在 PLM 内逐条确认（或按本表批量替换后复核）。
- **不参与查重签名**：`normalize()` 未改，查重簇数保持 541 不变；统一只作用于「建议写法」与「校验提示」两层。
- **西里尔/希腊混形字符**（如 `DС` 里的 С U+0421、`DQM-II/Ι` 里的 Ι U+0399）：未纳入替换表，因为无法可靠区分是笔误还是原意，需人工判断。

## 八、维护

- 判定是否该加：用 CP936 往返测试确认是否可表示，再判断语义是否唯一。
