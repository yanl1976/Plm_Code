# 选型库导入 · 问题与修复记录

> 每次导入出问题，先查本文；解决新问题后**必须补一条**。
> 相关代码：`src/plm-server.js`（`parseExcelBase64` / `cleanRowsByModel` / `importSeries` / `buildRowSpec`）

## 一、导入链路

```
上传 Excel
   ↓  POST /api/plm/select/parse
parseExcelBase64()
   · XLSX 读第一个 sheet，sheet_to_json({ header:1, raw:true, defval:'' })
   · 表头行：前 15 行里「非空单元格最多且不重复」的一行
   · 表头与数据统一全角转半角
   ↓  cleanRowsByModel()      ← 合并单元格清洗（本文重点）
返回预览（行数 + 清洗统计）
   ↓  人工确认列映射（勾「进规格」）
   ↓  POST /api/plm/select/import
importSeries()
   · 再跑一次 cleanRowsByModel（防止绕过）
   · 写 data/selection/series/<小类>/<系列>.json
   · 备份旧文件到 .history（保留 5 份）
   · 自动重建 accessory-dict.json
```

## 二、已知问题清单

### 问题 1：导入报「第 N 条数据的型号为空」，但文件看起来正常

**现象**

```
第 1727 条数据的型号为空
```

文件在 Excel 里明明每一行都有型号。

**原因**

型号列存在**合并单元格**：一个型号在视觉上跨了多行，XLSX 解析后只有左上角那格有值，其余为空。旧校验「一条空就整批拒绝」，所以整份文件都导不进去。

**处理**

`cleanRowsByModel()` 做**前向填充**：

| 情况 | 处理 |
|---|---|
| 型号空，该行其他列有值 | 沿用上一行型号 |
| 整行所有列都空 | 丢弃（表尾空行、分块间隔） |
| 第一行型号就空 | 报错「型号列在第一行就为空，请检查表头行是否识别正确」 |

**验证过的边界**

```
合并单元格续行    → 保留 4 行，补型号 2 行
表尾/分块空行     → 保留 2 行，丢弃 2 行
首行无型号        → 报错
正常数据          → 无改动
```

### 问题 2：选型助手列表里某列是空的（如额定电流）

**现象**

选型库管理页和选型助手的表格里，个别行的「额定电流」显示空白，前后行都有值。

**原因**

**不只是型号列**——合并单元格可能出现在任意列。举例（施耐德 EVS 样本）：

```
第 1254 行  EVSS12H3F601
  额定电流 = 空     ← 与上一行合并
  分断能力 = 空     ← 与上一行合并
  接线能力 = 空     ← 与上一行合并
  其余列有值
```

早期只对型号列做了前向填充，其他列漏了，于是 `/api/plm/select` 里 `current: row['额定电流']` 取到空。

**处理**

清洗扩展为**所有列前向填充**，但**排除自由文本列**：

```js
const NO_FILL = /说明|备注|描述|摘要|注释|comment|remark|note|desc/i
```

**为什么排除**：实测螺栓样本的「中文说明」若参与填充，会把上一行螺钉的描述（`内六角沉头螺钉|粗牙普通螺纹 M10…`）写到下一行，属于误填。

**已导入数据的补救**

清洗发生在导入时，历史数据不会自动重洗。补救方式二选一：

```bash
# ① 重新导入该系列（推荐，会重新走清洗）
# ② 跑一次性补救脚本（自动备份到 .history）
```

**干跑先看影响面**（务必先跑）：

```bash
node -e "..."   # 逐格比对备份与当前，确认只有「空→有值」
```

### 问题 3：规格回填只有型号，勾选「进规格」的参数没进去

**现象**

选型助手选完型号，规格框只有 `EVSS04N3F200`，缺极数、电流、分断能力等。

**原因**

`/api/plm/select` 里 `spec` 直接等于 `model`，而 `model` 只走**范式拼装**：

```js
const guided = composeSpecByGuide(seriesSub, row, cols)
const model = guided || suggestSpec(rawModel)
items.push({ model, spec: model })      // spec 与 model 同值
```

100101 的范式模板是 `{型号} {壳架}/{额定电流}A {分断能力} {极数} {额定电压}`，但施耐德样本**没有「壳架」列**，拼不出来 → 退回纯型号。

**处理**

拼不出范式时，改用**按列定义拼**（`buildRowSpec`），并严格尊重「进规格」勾选：

```js
const byCols = buildRowSpec(row, cols, modelCol)
const spec = guided || byCols || model
```

`buildRowSpec` 规则：

- 型号打头
- `specPart === false` 的列跳过（这就是管理页勾选框的作用）
- 占位符 `—` / `-` 跳过
- 型号里已包含的值不重复写
- 数字列自动补单位（`A` / `kA` / `V`）

**验证**

```
100101 / EasyPact EVS+
  model : EVSS04N3F200
  spec  : EVSS04N3F200 3P 400A Trip System 2.0 二段保护 50kA 440V

100105 / 3WT
  model : 3WT11N04 3P LSI/LSIG400A 55kA 500V
  spec  : 同一串（范式拼装正常，未受影响）
```

### 问题 4：技术参数框混入其他品牌的配件

**现象**

100105 下选西门子 3WT，技术参数里却出现正泰的 `S9 / V9 / XF9 / 安装辅材`。

**原因**

两处：

1. 字典按**小类**汇总，没有系列维度
2. 接口重写时漏了 `sub` 过滤，导致任意小类都返回 100101 的配件

**处理**

- 字典改为按「小类 + 系列」两级存储
- 接口先按 `sub` 过滤，再按 `model` 匹配系列
- 系列名含中文（如「螺栓选型清单」）视为**通用**，不参与型号匹配

**验证**

```
100105 + 3WT11H04  → 13 条
100105 + NB8-40J   →  5 条
100105 + iC65N     →  0 条（字典无该系列，不拿别家凑）
100101             →  0 条（无字典数据）
```

## 五、补充新问题的格式

解决一个新的导入问题后，在第二节追加：

```md
### 问题 N：一句话现象

**现象**：用户能看到的报错或异常
**原因**：真实的技术原因（不要写"可能"）
**处理**：改了哪个函数、什么规则、为什么这么改
**验证**：修复前后的对比数据
```

> 约定：**原因必须到底层**（例如"合并单元格导致解析后为空"，
> 而不是"数据有问题"），否则下次同类问题还会重来。
